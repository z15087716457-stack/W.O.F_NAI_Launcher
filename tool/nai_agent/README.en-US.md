# NAI Agent runtime host

This is the production business host using official Pi 1.5.0 directly. The adjacent nai_agent_sdk_probe retains stage A mock verification. Keep the exact npm lockfile and PI-LICENSE with the source.

Run npm ci --ignore-scripts --no-audit --no-fund, then npm test in this directory. Node >=22.19.0 is required. Release packages bundle Node 24.18.0, pinned dependencies, licenses and built-in skills (skills/nai-studio, skills/nai-prompt) under Studio's tools/nai-agent. Production uses only its bundled Node and host.mjs; users do not need to install Node or Pi.

The Flutter entry is lib/presentation/providers/nai_agent/. The workspace controller persists directories, chat metadata, composer drafts and original attachments; the starter resolves existing model configuration/secure storage and creates a private stdio child on demand. The host starts when a chat needs it; toolbar and collapsed widgets check `ref.exists` before reading the controller to avoid initialization solely for status display. Pi exclusively owns conversation history; workspace switching does not change the generation page. Source and installed-package states are recorded separately; see the repository's DEVELOPMENT.md for delivery instructions.

Seven entry tools are declared by default: read/write/edit/bash, studio_context, model-only ask_user and official codemode. Studio operations use the official in-process MCP transport in the nai_studio group, with codemode exposure and searchTools/describeTool/describeNamespace discovery; lib/domain-tools.mjs and the Dart tool_catalog.dart define the actual catalog. Native deferred extensions provide session_history and agent_manage without expanding the seven default entries. Only a short routing map is appended to the caller's system prompt; full business routes are read on demand from the MCP namespace. The explicit resource loader excludes global Pi settings, environment credentials, additional AGENTS files, unselected extensions and network model catalogs. Studio reads the project-root AGENTS.md and includes it in the effective system prompt. Studio supplies selected skills, prompt templates and Pi package resources to the official loader. Pi owns streaming, tool execution, retries, compaction, follow-up/steering queues and session files.

E7 uses the official DefaultResourceLoader for the built-in nai-interaction extension (studio_context and model-only ask_user), plus local Pi extension files/package folders explicitly selected through extensionPaths. Settings allow enable/disable/removal; the next send after the current task restores the session with changed configuration. Pi owns tools, slash commands and session_start/session_shutdown. Standard select/confirm/input/editor calls use native question cards; notifications, status and string widgets use the panel. Stop cancels both startup and running UI waits. Terminal custom components and other desktop products' proprietary plugin protocols are unsupported. Extensions run local code; binding cwd does not sandbox system permissions.

JSONL protocol version 1 carries private initialization config/mcp only on stdin. Other commands carry workspaceId/sessionId. Commands include prompt (followUp/steer), state, session_list, rename, system_prompt, queue_edit, navigate, compact, abort, shutdown and mcp_command (status/reconnect/login/logout). Tool requests/results/cancellations correlate by toolCallId. request_permit/permit_result/request_cancel/request_release share Studio concurrency. Late results are ignored and errors are thrown back to Pi. stdout is structured; stderr is not forwarded. costKnown=false means actual provider billing is unknown; Pi's internal zero placeholder must not be displayed as free.

Studio Chat Completions, Responses, Anthropic Messages, Gemini GenerateContent and Ollama-compatible protocols use official Pi adapters. Existing stream=false overrides belong to non-streaming calls and are replaced by streaming. Model/conversation/tool routing fields cannot be overridden. Gemini REST generationConfig maps to the Google SDK config; sampling gates and endpoint paths are explicit. Retries and request timeouts use provider settings. Unknown context/output limits currently fall back to 32768/4096 while public configuration retains null. Images require confirmed model support and provider permission. Unknown tool capability stays null; explicit false rejects startup.

Credentials and headers never enter prompts, sessions or command-line arguments. Provider errors that echo credentials are sanitized before Pi persistence. Secure headers/model body options come from existing storage. Flutter grants Pi request permits through the same per-provider gate used by translation requests. Waiting is cancellable and excluded from network timeout. Explicit runs default to 32 model requests (configurable 1–200); hitting the limit saves progress and requires explicit continuation.

Persistent data defaults to agent-data/ beside Studio, outside Flutter data/. Workspace IDs are separate from display names. Chat metadata only references official Pi JSONL; empty chats never fabricate Pi history. Original attachments remain in their workspace and upload copies use the existing image optimizer. Interrupted runs and pending inputs are restored for review without automatic sending. Message editing uses Pi navigateTree to retain abandoned branches. Running background chats continue after switching; idle children close to avoid accumulating memory. Generation snapshots can be saved; full draft/block restoration is available through the existing snapshot tool. Managed workspace data lives under project-root .W.O.F/ while cwd remains the project root; this includes sessions, attachments, snapshots, skills, instructions and MCP credentials. Existing backup/migration handles older workspaces and existing project files take precedence.

Tests use temporary workspaces, synthetic images/drafts and local HTTP/SSE. They exercise serialization and tool rounds for all five protocols, timeouts, image capability rejection, error redaction and override controls. Flutter separately verifies the production writer, backup/version conflicts/cancellation and the complete Dart → Node → HTTP → three-tool path. The separately authorized CPA test is recorded in project stage B documentation; npm test never contacts a real account.

MCP Settings and deferred agent_manage share configuration services. agent_manage also reuses native Pi package/resource handling for skills, extensions/packages, instructions and templates; resource changes apply on the next idle send in the same chat. Settings initialize enabled MCP connections automatically and keep display names separate from server identifiers. MCP settings manage the built-in group and user servers together. Supports stdio/Streamable HTTP, enable/disable, reconnect, official OAuth sign-in/out and codemode/deferred/direct/hidden exposure. External configurations use existing encrypted storage; ordinary settings contain metadata references only. Official OAuth stores credentials in the current workspace .W.O.F/mcp-auth.json, never the user global Pi configuration. Only explicitly selected servers connect. Stdio children and environment variables are user-selected local capabilities, not an OS sandbox. Legacy SSE is unsupported.

CodeMode runs official QuickJS; no replacement executor was added. MCP calls retain Studio backups, version checks, confirmations and cancellation. A Pi tool_result extension preserves native image metadata in official session details, aggregates CodeMode artifact paths and restores image previews with chat history. Built-in MCP uses a 24-hour deadline so user confirmation/long upscales are not cut off by the external-server default of 60 seconds; an explicit CodeMode timeout_ms remains a deadline for the whole script.

MCP reconnection restores available tools from the official transcript while respecting hidden/disabled tools and later unloads. The existing JSONL passes agent_settled.aborted and tool durationMs. Pi 1.5.0 uses the same host protocol, MCP helper interfaces and cache-warming adapter; 1.3.0 session compatibility has been verified. Tool declarations still use typebox directly to produce JSON Schema; Pi's pi-schema owns runtime argument validation and coercion.

Skills (2026-10-18): the host enables Pi's native skills with sources chosen by Studio — built-in `skills/` (read-only, updated with the app), global `agent-data/skills/` and the current workspace `.W.O.F/skills/`; on a name conflict workspace > global > built-in. Workspace `.agents/skills` or `.pi` folders are not read. `lib/skills.mjs` parses with Pi's loader and applies switches and manual-only mode; Pi formats the catalog and expands `/skill:`. `list-skills.mjs` gives Settings the same result. The system prompt keeps only an entry map; business tool usage lives in `nai-studio`.
