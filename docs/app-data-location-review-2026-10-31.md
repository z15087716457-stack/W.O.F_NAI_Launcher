# 应用数据直接使用相邻目录

2026-10-31。已与补全精简、发送回底、会话连续删除一并随本机 **2.2.3+73** 安装，未推送 Git；[本机交付](local-2.2.3-build73-2026-10-31.md)。

## 问题与实现

Setup 已通过登记的 `InstallLocation` 继承安装目录，并排除相邻用户数据；此次未修改安装器。原问题在于插件仍从全局 AppData 读写，再借兼容联接导回相邻目录，新装也会建立这个“旧目录”。原启动流程要求联接与当前安装匹配，即使已有本地数据，另一安装的联接仍会阻止启动。用户截图的具体错误详情未能取回，以下修复针对源码与隔离复现确认的这条依赖。

- [`application_storage.dart`](../lib/core/storage/application_storage.dart) 在存储打开前统一初始化：凭据插件经原生路径接口直接使用当前 `user-data`；偏好复用已有沙箱文件实现，保持原 JSON、`flutter.` 键前缀及串行写入。沙箱与正式运行共用实现，沙箱凭据仍只在会话内保存；没有新增独立存储系统。
- [`app_support_directory.dart`](../lib/core/utils/app_support_directory.dart) 保持 EXE 相邻目录为唯一当前根；旧位置只按 Windows `APPDATA` 与原生历史身份解析，不调用会创建旧目录的系统支持路径入口。初始化完成后再启动业务存储。
- [`adjacent_app_data_migration.dart`](../lib/core/services/adjacent_app_data_migration.dart) 删除日常联接归属检查、首次新装联接创建，以及分叉后的改名／建联接／撤销写入分支。已有当前资料优先，另一安装或断开的旧联接不阻止启动，也不改指向。原 `schema=1` 新建配置仅一次性补入已确认旧插件目录中的缺失文件，保留源与独立备份，当前文件不覆盖；核验后以 rename 发布完整文件。`schema=2` 后不再检查旧目录。
- 真正首次迁移完整旧资料时，原完整备份、SHA-256 校验、源变化检查及绝对路径兼容仍保留；既有 Python 环境与历史路径不删除。恢复 UI 继续处理真实的目录准备失败。

生产 Dart 代码相对本轮基线净减少 **103 行**。依赖仅把已锁定平台接口标为实际使用及增加原生插件测试引用，版本均未升级；校验脚本同时报告当前相邻目录与历史目录。
