# 小百科配图全库兼容性复核 · 2026-11-16

后续已按用户授权完成[原生实现与验证](wiki-image-panel-2026-11-16.md)。下文保留调查当时的统计与建议；当前有效引用计数排除了教程代码和零编号，实施／交付状态以上述报告为准。

结论：右下图片窗的布局方向可保留，但 `solo` 预览的固定“示例／非示例”两组不能直接作为通用实施方案。需按真实章节组织、保守搬运正文中的图片内容，并补齐两种素材类型、译文写法和大图集读取。本轮只读调查与临时探针，没有改生产功能或预览。

初次接口核验、现有组件和预览材料见[图片窗调查](wiki-small-images-investigation-2026-11-16.md)。本报告补充的真实内容边界优先于把该预览直接照搬成通用逻辑。

## 范围与证据

- 实际安装包的相邻 `user-data/dictionary_updates` 为读取起点，非旧工作树或安装包内的扁平 Wiki。当前修订 `b64a80c5c9de641a0f2900bfaf69c35b43256dfc34e9100f1b915be2f9b0b470`，数据库 167,804,928 字节。旧 Roaming 副本修订相同；本次明确使用相邻运行数据根。
- 原文全库扫描 298,922 篇，含明确 `!post`／`!asset` 数字标记的有 47,541 篇、115,561 次引用。这是文本引用统计，未对全库联网验证图片可访问性；其中两篇教程里的 17 个引用只是代码示例，应排除。
- 登记 SDK 下直接调用当前 Dart `WikiExampleReference.parse` 扫描这些图文文章，实际选中 10,836 篇、19,497 个去重帖子引用，与独立统计一致。现有解析只接“示例”章节的帖子图片，约 77.2% 含标记文章一项也选不中；此限制针对现有解析，不代表即将实现的新方案已经丢图。
- 当前相邻翻译缓存有 226 条完整译文记录。每标签取最新保留记录得到 151 个标签，其中 38 篇与当前原文 hash 匹配；22 篇带图、共 75 个唯一图片引用编号。未读取当前模型路由，也不把历史 hash 不匹配的 113 篇当作现行显示故障；既有缓存读取会校验原文 hash。
- 所有统计、样本与真实解析器结果在 `.dart_tool/wiki-content-audit-20261116/`。仅读取本地百科与文章译文；未调用模型、NAI、桥接或图片接口，也未写用户缓存或索引。

## 必须调整的内容边界

| 发现 | 当前证据 | 实施约束 |
|---|---|---|
| 章节不限于两组 | 图片最近标题为 Appearance 的引用 53,597 次、Costumes 4,552 次、Official art 2,006 次；629 篇含三个以上图片章节 | 分组来自原章节及层级，只有一组时不显示多余切换；多组采用能容纳长名称的现有选择组件，不能把“外观／服装”硬塞进“示例” |
| 非示例可能嵌在示例下面 | `zako_pose` 有 `Examples / Non-examples`，当前正例章节作用域会继续包含该子章节图片 | 反例由实际所在章节判断，不能无条件继承祖先的“示例”身份 |
| 素材图片占比不可忽略 | 14,828 篇含 `!asset`，34,621 次引用；与帖子图片混用 3,434 篇 | 引用需带 post／asset 类型，沿用各自的官方元数据读取；不把 Asset 编号当 Post 编号 |
| 说明经常缺失 | 38,188 次引用没有同一行的配图说明，约占原始引用 33.05% | 优先现有配图说明，缺失时用章节／词条名和来源编号；不额外请求模型命名或编造示意 |
| 说明不一定是纯文本 | 790 篇、2,875 条说明含 `[b]`、`[i]`、`[br]` 等 DText 样式；6 条超过当前截断的 240 字符 | 清理／转换已有标记并完整换行，不能让原始标签漏到名称里；图片编号不替代说明 |
| 译文会改变标记 | 对应当前原文的 75 个编号全部保留，但 5 处由 `!post` 改成 `post #编号`，包含 `1girl` | 图片列表取原文；译文按来源类型／编号寻找明确的图片条目，不依赖感叹号、固定标题或原文行号 |
| 同图可能有两个语境 | 48 个重复引用键，其中 43 个有不同章节或说明；`alcremie` 同一素材分别解释奶油类型与糖饰类型 | 元数据／图片字节可复用，显示条目保留各自章节与说明，不能按编号全局合并后只留一份说明 |
| 旁边段落不等于图片说明 | 172 处无行内说明且紧邻下一行文字；`20_minutes_adventure_(meme)` 在两个图片之间有独立解释段落 | 只搬确定的图片引用及专属说明。跨行、表格、折叠、混合段落无法可靠拆分时保留正文，避免误删定义或判定条件 |
| 图集会超过当前上限 | 54 篇超过 64 个原始引用；最大 `list_of_shining_nikki_outfits` 778 项，Splatoon 武器列表 378 项 | 64 是现有 API 批量大小，不应变成永久总量截断；按组／可见范围继续读取，不一次加载全部图片，也不在只展示前 64 项时移走全部原文 |
| 教程标记不是实际插图 | `help:dtext`、`howto:wiki` 共 17 个代码文字里的嵌入标记 | 排除代码／字面量区域，保留普通帖子文字链接和段落中的引用，避免误取图及误删教程 |

补充：20 篇原文被宽松 `![...](...)` 形状命中，实际抽查是感叹号、`[br]` 与 Wiki 链接相邻造成的误命中；全库未发现标准 HTTP Markdown 图片语法。因此没有证据要求扩展为任意 HTML／外链图片抓取。

## 可复核的代表词条

- `solo`：3 张示例＋3 张非示例，适合验证目前的两组预览，但不代表全库。
- `hatsune_miku`：11 个图片引用都在“外观”，当前解析器返回空。
- `.52_gal_(splatoon)`：多张 `!asset` 外观图，当前解析器返回空。
- `alcremie`：19 个引用分布在官方立绘与多种形态，且同一图用于不同分类，当前解析器返回空。
- `20_minutes_adventure_(meme)`：无章节、没有行内说明，图片之间的解释必须保留。
- `list_of_weapons_in_splatoon`：378 项、多个武器子章节、粗体说明，覆盖分组、样式与分批读取。
- `help:dtext`：代码示例必须原样保留，不能把 `!post #1234`、`!asset #1234` 当作真实图片。
- `1girl` 的保留译文：两项图片被写成普通 `post #编号`，应通过原文身份关联，不能只匹配 `!post`。

## 修订后的实施建议

保留已讨论的右下图片窗、图片名称／说明、单击灯箱、限高独立滚动及窄窗下移。把固定两组改为源文章章节分组；单组不加冗余切换，多组较多时使用现有下拉选择。`solo` 仍可呈现“示例／非示例”。

原文只负责确定引用身份和语境，当前语言的译文可提供对应说明。正文投影只搬明确的图片条目和说明，剩余段落与非空标题保留；同图跨章节不丢语境。沿用已有翻译链路，无需让模型再判图或新增提示词分支。

上述边界尚未实施。本次原生代码及预览保持，等待后续明确开工；13 项既有图片检查来自上一轮，本轮补充的是一项实际全库 Dart 解析器探针及独立只读统计，不把两者混称为已完成适配。
