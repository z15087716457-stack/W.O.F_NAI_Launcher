# 标签检索与语义补充重构

> 交付状态：已随 [r23 本机更新](cumulative-preview-r23-2026-10-17.md) 安装到原桌面入口，内部 `2.0.0-preview+27`；正式向量仍 0，未自动启动或建库。下文保留功能开发／测量当时的状态。

按用户开工授权实施，保留 EmbeddingGemma 与 Qwen 重排。源码接入中文资料、调整召回与结果更新，并完成翻译补缺的持久存储。本机桌面仍 r22，本轮没有覆盖运行包或启动正式建库。

## 检索结构

- 标签仍在同一个 pool-v2 中，每个实际标签一个 768 维 f32 向量；表示升级为 `tag-profile-v2`：名称、实时类别、中文核心词／同义词／简释义、官方别名、可用 Wiki 截段。没有把全部词库扩成四份向量，Wiki／积木／图库的来源与表示保持。
- 53,860 条补充资料只给实时词库中存在的名称提供参考；未匹配名称不自动加入主库。完整英文名称／官方别名检索保留，Danbooru 和 e621 类别沿现行映射识别。
- 召回在视觉类别内保留配额，同时保留名称类别通道；精确实体查询使用完整名称召回。处理前按当前词库、资料摘要及已有标签／别名重新核验，避免少量全库候选被不相关实体占满，也避免一概删除实体。
- 中文复合描述使用资料中的核心名称保留最多四个概念，每组最多八个实际候选。较长嵌套词优先，一字核心还需同资料中较长名称佐证；否定提及不固定到前列。普通场景中的实体名称不会仅凭含有某个常用词就成为固定概念。扩展词可辅助召回，但不能冒充 canonical alias。没有额外请求远程模型来分词或改写查询。
- 重排收到类别与语义资料。手动查询使用专用 `tag_search` 指令，判断标签本身的含义及其表达的描述部分；空框仍用原正／负上下文补充指令，其他文字来源仍用 `retrieval`。核心概念各保留一个重排后的代表，兼顾整句相关与概念覆盖。
- 召回预算为 `max(80, 2 × 展示上限)`，重排按展示数量加约 20% 余量、向 8 的批次取整。40 条时重排 48，80 条时重排 96；移除原来最多 32 项的隐藏限制。精确命中、概念、语义、普通／共现来源与原始分数随结果保留到 Dart 候选，仅存在内存，不记录用户查询。

## 弹窗与共用入口

手动搜索立即保留精确命中，其他结果在语义查询完成后统一发布；失败、无向量或资源让出时回落普通结果。新查询清除旧候选并沿用序号／取消保护。空框先显示至多 12 个、且不超过展示上限一半的共现／常用候选，语义结果追加到后面，不把这一组挤走；没有语义命中时恢复完整普通列表。

悬停、键盘选择与草稿版本保护继续生效。所有共用标签框可以执行明确输入的本地语义搜索，只有原来启用上下文推荐的输入框才传光标窗口；手动查询始终不传原提示词。正负面、角色、权重、原提交路径与空格查询语义保留。修复 `character_(work)` 的右括号被当作权重外框裁掉的问题。

## 翻译与持续补充

- 名称请求输出升级为 `tag / name_zh / definition / core_zh / synonyms_zh / summary_zh / wiki_zh / wiki_original`。阅读字段跟随阅读语言，三个语义字段固定简体中文；正文仍仅在打开后按原完整 Wiki 流程翻译。
- 优先复用随包资料、用户补充及有效旧中文译文。已有名称不能让缺失语义字段被跳过；完整资料可直接提供中文阅读，不需要配置远程接口。已有个人阅读优先保留。已有字段、数组形状、长度、去重与核心词顺序均校验，既有语义字段不能被返回值擅改。
- 缺可靠语境可返回未知，不虚构身份或说明；相同语境／提示词版本的有效未知结果不反复请求，手动重试或语境变化后可再补。自动开关、可见范围、五并发、取消、失败提示与重试沿原链路。未恢复聚合翻译、session 复用或后台全库补翻。
- 用户资料保存于 `user-data/tag_semantics/supplements.db`，独立于可清理的译文缓存。设置页新增导入／导出；导入先整体验证，事务补缺并保存导入前 JSON，不覆盖已有本地字段。随包资料始终只读。
- 当前请求的语境 hash 与简释义的来源 hash 分别保存，防止一次新尝试把旧释义标成当前资料；不再匹配的说明不参与当前检索。只有内容变化递增语义 revision，单纯记录尝试不触发向量更新。
- 完整基础来源未变时，后续仅核对 revision 之后改变且仍在主库的标签，更新相关向量；取消后可继续。基础词库／Wiki／表示变化沿完整核对，但只重新嵌入摘要改变的记录。保留共享检查点、断点和内存映射策略。

## 验证与实测边界

证据目录：`.dart_tool/tag-retrieval-refactor-20261017/`。所有模型试验使用现有本地 CUDA 权重、公开固定查询与独立语料／索引，不打开正式向量进行查询，不请求云模型或 NAI。

51,185 条混合语料包含随包主库可对应的中文资料及额外实体名称；同一组名称分别构建旧表示与新表示。最终搜索用当前源码重新打开检查点，保留原模型；旧实现固定自 `c37663a00` 的 `engine.py`，共用本轮上下文解析与池读取代码，因此属于检索结构对照，不是两个已安装整包的比较。

同语料仍为 51,185 个向量：检查点目录约 360.3→375.8 MiB，增加约 15.5 MiB；打开后进程驻留约 55→54 MiB，模型与查询后约 2.21→2.24 GiB。独立进程首次查询含模型加载约 10.90→10.91 秒，后续十个查询中位 223→492 ms。未清操作系统文件缓存，不算整机冷启动；重排候选更多且增加资料核验，本版不宣称比旧版搜索更快。初次构建时存在并行编译等干扰，不用构建耗时比较收益，也不线性外推完整库内存。

413 项 Flutter 与 114 项 Python 检查通过，共 527 项，0 跳过；覆盖输入与别名、请求取消、选择冻结、普通回落、类别配额、概念及否定、80 条上限、缓存迁移／未知补缺／语言隔离、来源 hash、导入事务与增量更新等。范围分析无诊断，Windows Release 与原生身份核验通过；1532 个记录的生产输入构建前后匹配，包内七个工作脚本、新资料库与许可文件匹配源码。
