# 共享池检查点、退出与统计优化 · 2026-10-17

按用户授权完成[性能调查](rag-startup-performance-2026-10-17.md)提出的三项优化。源码已完成并验证，**尚未构建／安装新桌面包**；安装版仍为 r20。本轮没有操作用户现有索引、运行中的建库任务、模型或界面。

## 最终实现

- **统一检查点所有权。** 共享 Engine 关闭时只释放自己的 SQLite 连接，最终由 Worker 持有的 VectorPool 保存一次。池记录成功载入／发布的 generation 与数量；向量未变且文件仍在时不再序列化。seen、暂停标记等不触发保存。恢复过的损坏检查点仍必须发布，保存／元数据切换失败不会被错误标为已保存，下次可以重试。原 ANN 文件、元数据布局和检查点有效性判断保持。
- **退出不再重建已提交的批次。** 生成器只在提交后的 yield 暂停；此时关闭直接释放生成器，保留 RAM 中与 SQLite 一致的向量，交给池拥有者保存，不再将正常 GeneratorExit 当作异常去全池 reload。其他异常仍回滚、恢复 ANN，正常完成／取消及周期检查点照常保留。
- **完整但有上限的退出。** Worker 先结束生成器、关闭分区连接、保存共享池，再卸载模型。即使某个收尾失败，仍尝试其余资源并报告有限失败事件。Python 主线程等待执行线程完成，不再于 15 秒后放弃守护写线程；客户端正常退出预算从 3 秒调整为 60 秒，期间继续排空 stdout／stderr、拒绝新请求并忽略迟到业务响应。达到期限才终止本次拥有的 Windows Job；异常失联仍走短收尾，不无限等待。池关闭后释放 ANN 和视图，重复关闭幂等。
- **重连与退出串行。** 设置变更导致旧宿主退出时，新连接等待旧宿主完成保存；应用退出也等待正在收尾的宿主，避免旧对象离开当前字段后仍被过早结束。
- **容量由事务维护。** 新增辅助 `pool_sizes` 表与触发器，按分区保持与原 `SUM(length(vector)+length(text)+length(name))` 完全相同的计算口径，包括 Unicode、NULL、更新、删除、分区移动和回滚。旧库每个分区首次查询时补算一次；以后只查摘要，真实数据变化在同一 SQLite 事务内增减。向量、ID、模型指纹、池目录、原记录及 USearch 文件不迁移或重编码。旧版会忽略辅助表，触发器仍可维护它。
- **首轮状态复用。** 等待新连接的 refresh 直接使用 configure 已返回的状态与已写好的来源快照，不立刻再执行第二轮 status。后续刷新仍请求最新状态，且不会用旧 configure 结果覆盖实时建库事件。

索引恢复的批次／线程策略、模型导入方式、CPU／GPU 策略、来源范围、检索候选／排序／重排规则均未修改；没有切换到只读内存映射。旧库首次补算容量仍会有一次读取成本，不承诺大库启动瞬间完成。异常断电或超出退出预算时，仍可能从已提交向量恢复；没有跳过过期检查点校验。
