# 数据补充检查更新与 Wiki 正文同步

用户确认实施后，已完成源码与功能验证，尚未安装到桌面。当前安装仍 r23 / `2.0.0-preview+27`；本轮不自动启动、下载补充用户数据或操作正式索引。

## 行为

- 数据补充增加持续可用的「检查更新」。首次进入只读本地记录，不联网；手动检查只请求公开文件元数据，成功区分已是最新／有可用更新，保存最后成功时间。失败保留当前数据、候选版本及上次成功时间，可重试。
- 检查两处现有公开源：GitHub 同规格 `_pt20-ia-dd.csv` 文件列表、Hugging Face 当前登记 Wiki JSONL。先取得不可变提交再读取文件元数据，内容未变的 README 提交不产生更新提示。Wiki 以后另建数据集需要另行登记，不自动搜索任意来源。
- 本次使用直接上游元数据，未依赖尚未发布的自有清单、创建后台轮询或推送 GitHub。成功检查的轻量记录保存在 `dictionary_updates/latest-check.json`，重启恢复，不代表自动下载许可。
- 只有点击对应更新按钮才下载；现有数据已安装时仍可检查。下载严格核对大小：Wiki 使用来源 LFS SHA-256；新 Tag 使用不可变 Git blob SHA-1 核对 Git blob 头与正文，并计算实际 SHA-256 存入本地发布记录。已知内置 Tag 同时核对 SHA-256 与 Git blob。不可把两个算法的标识互相比对。
- 下载、校验、后台导入、不可变数据库发布、取消和失败保留原库继续复用；检查与导入互斥，重复点击共享任务，过时来源不能覆盖已安装的较新日期。按钮悬浮提供可用版本、大小及已安装日期。

## Wiki 迁移与保护

Wiki 从只补缺失改为按上游规范名更新正文，仍跳过删除标记、空文章和无效标题，保留未出现在该快照中的已有文章。重复规范名优先使用更新日期较晚的正文，同日期／日期未知保留首条；新增和更新分别计数，同一旧文章只计一次更新。

旧版已安装同一 Wiki 快照但尚未应用正文同步规则时，显示「Wiki 正文可刷新」和「刷新 Wiki」，不冒充发现了上游新文件。悬浮说明需要重新下载当前 Wiki 数据、保留个人译文；完成后记录 `mergeVersion=2`，不再重复提示刷新。

Tag 继续保留既有类别与其他站点标签、补充名称和别名、使用次数取最大值，并统计已更新条目。个人译文、个人语义资料和共现库不在发布范围；活动原库不原地覆盖，失败／取消继续可用。成功后刷新标签／百科查询，已存在的自动翻译控制器重读当前语境，在持久缓存中保留个人内容并按既有 hash 检查定义与语义适用性，不全库补翻。

本轮不改 RAG 许可、不清空或自动重建向量。现有 worker 保持已配置的旧来源路径，成功数据更新后会提示：若使用语义检索，重启 Studio 后手动同步对应来源索引。仅更新原始资料不能宣称向量已同步。
