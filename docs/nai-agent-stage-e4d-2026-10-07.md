# NAI Agent E4D: native reference library import, apply and export

2026-10-07, Asia/Taipei. Valid source: `E:/A.I/NovelAI/.devin/wt/nai-launcher-src`, HEAD `af54e9ac`. The full E/F product remains in progress. The production catalog and official Pi routing map now expose 19 actual tools.

`reference_library` uses the existing Vibe and precise reference services, with six actions: query, read, apply, import, save and export. Query uses the native lightweight library index without changing the screen's search/filter state. Reading loads only the selected entry/file, returns actual model, encoding availability, parameters, child indexes and a content version; it excludes encoding strings and image Base64. Original library pixels are available through `image_read` reference IDs. Pre-encoded references with no original or preview return `image_missing` honestly while remaining usable for applying their encoding.

Imports accept workspace-relative native `.naiv4vibe`/`.naiv4vibebundle` files and the existing parser's image formats, or actual Studio image IDs. Saving copies current Vibe references or one precise reference into the native library without changing the draft. Precise imports retain original pixels and native type/strength/fidelity. Applying a precise reference uses Studio's normal PNG canvas normalization. These operations neither encode a Vibe nor generate an image; generation-time encoding remains subject to the existing quote/approval path.

The old native Vibe save path rebuilt a file from the selected parsed encoding. New explicit original-file storage/import methods preserve the complete original native JSON file, including encodings for additional models. Whole-file export copies that file byte-for-byte. Child exports and newly saved current references use the native codec. Export creates a fresh folder beneath workspace `outputs`, returns a relative path and never overwrites an existing user file.

Applying requires a fresh draft acknowledgement and, for a library ID, the entry version returned by read. The binding backs up the complete native draft/workflow, rereads the reference source after that IO and checks edits, Stop, binding lifetime and active jobs before the synchronous native draft write. Bundles exceeding the remaining 16-reference capacity reject as a whole; a caller can select one child explicitly. Import/save are additive native library commits: after admission their file/index commit completes without rolling back unrelated edits. Open library views reload while retaining their filters; closed views are not initialized. This stage does not update usage counters or add library rename/favorite/category/delete actions.

Workspace file reads reject absolute paths, traversal and resolved links outside the workspace. Inputs/exports are bounded to 64 MiB and reference images to 64 million pixels. A real output-directory redirect (symbolic link or Windows junction) is rejected before writing outside the workspace. This is domain-file validation, not a claim that arbitrary Pi shell commands are sandboxed.
