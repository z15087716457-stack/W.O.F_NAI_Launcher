## 当前规则

SQLite 继续保存各来源完整的 768 维 f32 向量、资料摘要和同步状态。`danbooru-search-v1` 使用原有精确 Torch 矩阵查询，共享 USearch 不再保存它的向量副本。Wiki、提示词块、图库画面和参数索引继续使用同一份 ANN；退役旧标签集合仍由明确升级流程处理，不提前删除。

来源键集合及计数独立于是否参与 ANN。新标签增删仍提交 SQLite、更新自身进度与搜索矩阵，但不把共享 ANN 转为可写，不写 ANN 变更日志，也不触发整图保存。容量摘要继续统计标签实际数据，界面不会因 ANN 中没有标签而误报空库。

检查点注明 `scope=non-tag-v1`。首次打开旧全来源检查点时，从 SQLite 已保存的非标签向量重新整理 ANN 并保存；不调用嵌入模型、不改变来源签名、暂停状态或原始向量。旧计数恰好相同也不能冒充新范围。完成后再次打开直接使用映射，不重复整理。

全局 generation 保持原数值并单调增加，仅跟随 ANN 成员变化；插入／删除精确标签不使图失效。来源在两个范围之间变动时，日志分别记录移出及移入的键，恢复只装入当前 ANN 成员。标签本身仍由 SQLite 事务保障持久化，退出或中断后可以继续使用已提交批次。

## 隔离样本测量

两个独立 Windows Python 进程、相同随机种子，16,384 条标签向量与 768 条其他来源向量。不加载真实模型，不打开用户索引；这些是一次合成测量，不是应用端到端耗时或全库内存承诺。

| 指标 | 改前 | 改后 |
|---|---:|---:|
| SQLite 标签向量 | 16,384 | 16,384 |
| ANN 成员 | 17,152 | 768 |
| ANN 文件 | 55,235,200 B | 2,470,000 B |
| 从 SQLite 恢复并保存 ANN | 0.624 s | 0.031 s |
| 修改一个标签并保存 | 0.089 s | 0.002 s |
| 修改标签后 ANN 文件字节相同 | 否 | 是 |
| 进程峰值工作集 | 157.43 MiB | 51.21 MiB |

两边更新后 SQLite 向量摘要相同，ANN 样本文件减少 **95.53%**。完整当前语料 1,004,407 条标签向量的一份原始数值为 3,085,538,304 B；实际节省还受 ANN 图结构和其他来源规模影响。查询需要的精确矩阵、SQLite 权威副本和模型内存继续存在。
