# 撤销文字边缘滤镜

2026-10-10 用户在探索页原型对照中指出应用小字笔画发歪、可见空隙疏密不均，并确认关闭滤镜正常、开启后异常。该反馈覆盖此前接受的浅色 0.70 补偿。

原型没有文字后处理。先前新增的着色器对文字透明度执行幂函数，让半透明字缘变深；0.70 是覆盖率指数，不是字号或字重。相同字体和布局参数不能保证经过离屏滤镜后仍保持相同字缘。

## 独立诊断

- Chrome 实际字形来源经 `CSS.getPlatformFontsForNode` 确认为自定义 `HarmonyOS Sans SC`；原型正文为 13px、400、正常体、行高19.5px、默认字距、词距0。
- 原生诊断使用与生产资源哈希相同的字体，13px、400、正常体、行高1.5、字距/词距0；在同一窗口比较无滤镜、1.0透传、0.70补偿，并包含四种小数像素位置、段落、带背景的富文本。
- `dynamic composition,` 原型跨度129.484375px，Flutter129.4669647216797px；逐字符原点最大差约0.012px。此样本的主要异常不来自任意设置的字距。
- 滤镜透传与原生结果在部分小数坐标、富文本背景仍出现像素差；不能用“指数1.0”代替彻底移除绘制路径。补偿只变深也不能修复像素位置/重采样问题。没有根据旧上游问题断言当前引擎根因。
- 原始 PNG、测量 JSON、构建与检查日志在 `.dart_tool/prompt-raster-diagnosis-20261010/`，不加工截图修饰结果。

## 修正

删除文字着色器及资源登记，删除 `StudioTextCoverage`、普通/富文本、输入框、可选文字的自定义滤镜包装。共用 `studio_material.dart` 只转导出 Flutter 原生 Material API。提示词语法控制器直接返回原有着色 span。`WorkspaceTypographyScope` 只保留100%文字尺寸。

字体文件、字号、字重、行高、提示词语法着色及业务数据不因撤滤镜调整。专用 Windows 实绘入口现在明确记录 `textPostProcessing: none`，素材和存储继续仅用内存样本，不调用生成接口。

本次仅处理文字滤镜，继续停在检查点⑤。未安装、启动、重启或热重载用户 Studio；开发目录 Release 仍是实绘入口，交付须用正常入口重建。
