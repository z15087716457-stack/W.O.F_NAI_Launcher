# 画布与历史栏：顺序、装饰与多选调查

2026-11-01，已按用户授权完成源码，尚未安装；当前实现及验证见[合并完成记录](generation-history-polish-2026-11-01.md)。下文保留开工前调查，不再作为待办。调查时涉及的 9 个生产文件与已安装 **2.2.4+77** 的冻结输入一致。

## 结论

问题已复现。同一批图片完成后，画布依 `batchIndex` 升序逐张排列，历史投影先拆成单图，再按各图 `createdAt` 降序排序。顺序返回时刚好倒序，并行返回时取决于完成时间。历史 UI 按投影顺序绘制，没有再反转；点击按图片 ID 定位，未发现图片身份错配。

原因位于 `lib/presentation/wiring/generation_view_mapping.dart` 的 `generationHistoryView`：`buildHistoryBatches` 已按批内序号整理，但 `.expand(...)` 之后的 `batches.sort(...)` 打乱了它。画布的 `groupCanvasImages` 则在批内排序后直接展开。开启分组、生成中的活动批次仍保持批内顺序；问题在完成后拆成独立行时出现。简洁查看器也共用这份历史投影。

## 最小修复建议

把现有批次排序放在单图展开之前：批次按新到旧排列，批内保留原有序号。沿用当前展示开关、投影和图片 ID；无需改变画布布局、UI、原图、真实批次或保存逻辑。待用户确认开工。

## 验证

5 个隔离探针覆盖顺序完成 2／4 张、并行乱序、开启分组、生成中到完成的变化。典型结果：画布 `0,1,2,3`，历史 `3,2,1,0`；并行样例画布 `0,1,2`，历史 `2,0,1`。加上已有投影与画布布局回归，共 **29 项通过**。原单图历史测试仅比对 ID 集合，未检查先后；后续修复应补顺序断言及跨批次覆盖。

## 主图区装饰与联动多选

用户随后调整要求：去掉主图区数量角标，蓝框只表示多选选中；历史栏与主图区联动，单张生成同样支持。此前“直接删除主图区蓝框”的建议不再作为实施方案。

现有蓝框是查看焦点：`generation_canvas_wiring.dart` 仅向多图组的焦点图传入 `focused: true`，共享 `GenCanvasTile` 据此画 2px 边框。简洁查看器也有同样条件。无限画布的 `_buildGroupBadges` 对多图组另画 `×N`，历史卡片独立保留数量。

现有多选只在 `GenHistoryPanel` 私有状态内保存批次 ID，操作前由 `_ids` 展开成该批全部图片 ID。主图区没有共享多选；现有单图右键删除已经可用，但无法通过历史栏细选组内若干图片。

建议将已有多选提升为两边共用的一份图片 ID 集合，沿用现有入口与操作条：历史封面选择整批，主图区选择单张；部分选中时历史蓝框配半选横线，全部选中时勾选。普通查看与批量选择分开，蓝框只对应实际多选项，单张组不再特殊处理。保存／删除／打包直接读取同一份实际选中 ID；分组切换不改变选中图片。无需新增设置或第二套选择系统。尚待确认开工。

隔离 widget 探针确认：选中双图组子图时蓝框为 2px、角标 `×2`；选中单张时焦点 ID 已变，但无蓝框或角标。1 项通过，相关 8 个生产文件与 +77 冻结输入一致。最初搬移测试夹具漏改一个相对 import，编译失败；修正夹具后通过，原失败日志保留。证据见 `.dart_tool/canvas-decoration-investigation-20261101/`。此探针只验证现状，联动多选尚未实现或验收。
