# 本地画廊文件变化同步

2026-10-23，用户反馈本地画廊与其他应用之间切换时频繁卡顿，确认采用文件变化驱动更新，并要求不添加防御性兜底。本轮仅改源码，基于 `a9158aac2`，不安装、启动或操作用户 Studio。

## 行为

- 删除原来的获焦后两段 500ms 延迟刷新及 5 秒节流。旧 `scan: false` 仍会枚举全部图库、stat、排序、清尺寸缓存、重载时间线并同步分类。
- 预热创建画廊服务前开始原生递归监听；主源、额外源的设置改变后调整订阅。退出窗口或进入其他分支时只积累事件，回到画廊后合并 500ms 再处理。无事件时不读取服务或文件列表。
- 排除缩略图、隐藏内部目录、分类配置及非图片文件。普通图片事件只读取这些路径；目录增删和改名只枚举受影响子树。批次串行，处理期间的新事件留到下一批。
- 文件索引共用原生扫描／移动锁，只查询事件路径的记录，保留原图片 ID、收藏、集合和软删状态；目录改名同时保留分类 ID。文件夹只重数受影响目录，祖先计数由内存聚合，未变化的分类复用原对象。
- 未变化的记录、尺寸和缩略图缓存保留。实际内容变化才重载同一数据集，滚动偏移和筛选保持；图片被原地修改时失效该路径的哈希、缩略图和解码缓存，异步旧缩略图不能覆盖新内容。
- 手动刷新仍完整核对图库和分类，并可重新建立已停止的监听。监听或批次错误直接进入现有错误状态；不轮询、不定时全量扫描、不自动重试或全库兜底。

## 验证

- 测试全部使用临时图库、独立 SQLite/Hive 或内存服务，没有读取用户图库、账号、草稿或索引，也没有调用真实生成接口。
- 原生 Windows 测试覆盖递归子目录新增及目录改名的旧／新路径；批次测试覆盖后台积累、合并、在途新事件、来源增删和销毁。
- 真实画廊组件反复失焦／返回，断言刷新次数为 0、时间线读取次数不增加、时间线对象保持；独立监控器验证 20 次切换无事件时不执行批次。
- 服务和分类测试覆盖局部增删改、改名保留图片／分类 ID 与收藏、软删不复活、当前筛选和未变化尺寸缓存保留；Notifier 验证只重读变化记录；组件以实际解码像素验证同路径修改后缩略图由红色更新为蓝色。
- 最终相关回归 **437 项通过、0 失败**，含画廊服务／分类／组件／页面、RAG 及 Agent 图库文件操作；日志见 `.dart_tool/gallery-file-changes-regression-final.log`。全仓 `flutter analyze --no-pub` 无问题，见 `.dart_tool/gallery-file-changes-analyze.log`；`git diff --check` 通过。这属于隔离测试结果，实际切窗流畅度由用户更新后确认。
