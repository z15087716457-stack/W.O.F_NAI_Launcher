# 主生图页无视觉改动性能调查

日期：2026-11-02。以本机 2.2.4+78 的冻结源码为准；仅调查及隔离候选验证，未修改生产代码、用户数据或安装程序。

后续状态：用户已确认开工，历史焦点框和前两项性能优化已完成源码与回归，尚未安装；第三项经计量暂不改。当前结论与证据见[实施报告](generation-focus-performance-2026-11-02.md)，以下保留调查阶段的依据。

## 结论与建议范围

有明确优化空间，优先减少视图数据中的重复工作。现有绘制代码、原图／预览分辨率、滤波、玻璃／模糊／纹理／光影／通道装饰、动画频率和相机行为均作为不变项。已有按模块订阅、图块裁剪、缩略解码、文本布局缓存和材质重绘隔离继续使用，不重新列为待做。

| 优先级 | 现状与证据 | 最小处理方向 |
|---|---|---|
| 优先：草稿重复读取与图片哈希 | `generation_data_wiring.dart` 每次总视图投影都调用 `readBridgeDraft`。其中 `p.copyWith(...).hashCode` 会经 Freezed 的 DeepCollectionEquality 遍历原图、蒙版等图片数据；仅进度变化也重复执行。 | 页面只读投影复用按真实草稿版本失效的结果。保持真正操作入口的实时 `readBridgeDraft` 和确认／冲突校验，不对它们做宽泛缓存。 |
| 可顺手做：同帧可见范围 | `generation_canvas_view.dart` 在 `tiles.where` 中为每个条目计算同一个 `visibleWorldRect(...).inflate(500)`。800 个条目、10 次求值就是 8,000 次。 | 在同一次 builder 中只计算一次，原过滤表达式／范围／顺序保持。表达式对照为 10 次计算，可见矩形与顺序完全相同。这是小优化，不推算 FPS 收益。 |
| 次优先：当前焦点的历史投影 | `generationFocusViewProvider` 仍订阅完整生成状态；`generationFocusView` 在仅进度变化时也合并历史、建立临时目录并过滤组成员。800 图、10 次更新实测读取 8,000 条历史记录。 | 复用现有图片目录和稳定的历史／几何投影，只更新活动生成槽。收益需结合历史规模验证，不为此另建空间索引或通用缓存管理器。 |

当前焦点历史读取只测了操作次数，未证明它是用户整机卡顿的主因。建议先做第一项和很小的可见范围改动，再决定第二阶段的焦点投影复用。

## 隔离数据与候选对照

材料：源码根 `.dart_tool/generation-perf-investigation-20261102/`。

- 原有 `generation_performance_test.dart` 的 **5 项检查通过**，确认旧优化没有失效：收藏请求去重／失效边界、流式帧复用几何和历史对象、批次边界索引、界面分区订阅。
- 新增 **4 项隔离探针通过**：历史读取计数、可见范围表达式等价、图片参数哈希耗时、实际总视图 provider 的进度更新。不同检查合计 **9 项**；重复候选运行不累计。
- 输入为合成字节，不读取或解码用户原图，不加载权重、不联网或生图；实际 provider 使用隔离 Hive、内存草稿和现有账号／Token／费用替身。
- 候选由当前 `generationViewDataProvider` 源码派生，只把页面的草稿读取收束为一个按 `bridgeDraftVersionProvider` 失效的只读 provider。其余计算和绘制实现不变，文件仅在审计目录。
- 对照在同一个 ProviderContainer 中进行，等待既有异步只读结果就绪，再比较当前与候选的所有 `GenAspect`。使用真实 `GenScope.updateShouldNotifyDependent`，界面所有分区投影均等价。

最终合成 JIT 对照，均为 20 次进度更新：

| 原图与蒙版合计字节 | 当前总视图投影 | 只读草稿复用候选 |
|---|---:|---:|
| 0 | 28.6 ms | 16.3 ms |
| 2 MiB | 188.2 ms | 14.0 ms |
| 8 MiB | 671.8 ms | 11.9 ms |

单独对当前 ImageParams.hashCode 做 20 次读取，0／2／8 MiB 的结果约为 0.09／162.2／647.5 ms，与图片数据遍历的增长相符。数字来自 Flutter 测试环境，只说明重复 CPU 工作的规模，**不是 Release 帧耗时、实机 GPU 性能或 FPS 提升比例**；基线先运行也可能带来 JIT 顺序差异。

候选早期用根视图对象身份以及跨容器未稳定的异步状态比较，断言失败。最终改用同容器、预热后真实界面分区的比较，未改生产代码或删减分区。初始与最终日志均保留。

## 实施前仍需覆盖

- 真正编辑提示词／块／角色、切模型／预设、参考图与图生图开关、导入和撤销时及时失效，不能把旧草稿留在界面。
- Krita／Agent 的实际读写、确认版本及冲突保护仍按原入口读取最新状态；不能因视图优化放松这些语义。
- 分组、单图、多选、Pins、停止／失败／重试、图像尺寸变化与流式占位的当前焦点和相机行为保持。
- 实施后以同输入、同主题、同视口和相机位置做截图及轨迹比较；像素和动效检查独立于计数结果，不降低视觉基准来通过。

## 另一个已确认的小修正

历史栏普通浏览的焦点蓝框应恢复，生成中占位同样适用；多选时继续按实际选中绘制。现有 `focused` 状态仍正常，当前边框条件只读取 `checked || partial`，属于显示条件漏项。主图区仍只在多选时显示蓝框。此项是用户另行确认的视觉修正，和性能优化的不变边界分开。
