# 图库固定长度列表异常 · 调查结论

后续状态：本问题已完成[源码修复与 165 项回归验证](gallery-fixed-list-fix-2026-11-04.md)，尚未构建或安装。下文保留本次排查时的状态与证据。

2026-11-04（Asia/Taipei）。用户截图显示“刷新图库失败：Unsupported operation: Cannot remove from a fixed-length list”。已通过当前安装版本对应的真实图库服务、临时 SQLite 和合成图片复现；本次仅排查，未修改业务源码、构建或安装。桌面保持 **2.2.5+82**。

## 根因与触发

`_getAllImageFiles` 在 `unified_gallery_service.dart:727–734` 读取软删除路径；只要记录非空，就用 `toList(growable: false)` 生成排除后的文件列表。初始化和刷新分别在第 612、1849 行直接把结果赋给 `_allFiles`；无筛选时 `_filteredFiles` 同样引用该列表。

文件监控的 `applyFileChanges` 在第 1806 行先调用 `removeImagesFromMemory`，后者第 1265 行对 `_allFiles` 执行 `removeWhere`，因此抛出固定长度列表异常。此时传入的路径即使是一张新保存、尚不在内存中的图，也会失败。软删除记录不要求刚刚产生，故触发取决于初始化／刷新和后续文件事件的组合，表现为偶发。

`local_gallery_provider.dart:58–62` 将文件监控错误转到 `reportFileChangeError`，第 1033 行使用通用 `refreshFailed` 错误码，所以界面显示“刷新图库失败”，不代表用户刚按过刷新。没有取得本次现场调用栈，结论依据截图、当前源码和隔离复现；不将合成事件冒充用户当次事件。

## 隔离验证

登记 SDK Flutter 3.47.7／Dart 3.13.5 下，**7 项检查通过**：

- 原有文件变化服务的 3 项真实数据源测试。
- 3 项异常复现：初始化前已有软删除记录后新增图片；运行中软删并刷新后新增图片；初始化排除软删除记录后再次从内存移除。
- 1 项对照：没有软删除记录时，同样的新文件事件正常更新。
- 新图已由索引处理写入临时数据库、原图／新图文件仍存在；异常发生在之后的内存列表更新。异常后调用刷新可重新显示新图，但列表仍是固定长度，因此后续相同事件仍可能再次失败。

实际堆栈为 `FixedLengthListMixin.removeWhere → LocalGalleryServiceImpl.removeImagesFromMemory:1265 → applyFileChanges:1806`。

最初临时夹具在后台初始化尚未结束时清理目录，出现文件占用并伴随后续绑定错误；按既有测试模式补齐 binding、模拟偏好及后台等待后，最终全部通过。初次日志保留，未为此修改生产实现。

## 最小修复建议

在扫描结果创建处，把这一处 `toList(growable: false)` 改为默认可增长的 `toList()`，保持服务内文件列表可增删的既有契约；不删除软删除排除逻辑，不清删除池、不改数据库、不添加异常吞掉或每次事件复制整库列表。

正式修复时将上述触发和对照改为对应正常增删／更新断言，纳入现有服务回归，再覆盖图库新增、删除、刷新与筛选路径。本次未实施修复，未把复现通过记成修复通过。
