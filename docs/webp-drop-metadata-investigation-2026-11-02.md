## 已确认的问题

`global_drop_handler.dart` 的 `detectImportableDroppedImageMetadata` 在调用统一解析服务前，直接过滤所有非 `.png` 文件名。拖入／粘贴 `.webp` 即使包含有效元数据，也返回 null；随后“使用图片”弹窗显示“未找到 NovelAI 元数据”，导入按钮置灰。入口已接受 WebP 并能显示预览，但没有执行元数据识别。

底层 `UnifiedMetadataParser` 和 `ImageMetadataService` 仍按签名识别 WebP，支持 EXIF 和 alpha 隐写。现成 `v4_webp_exif_stealth.webp`（187,744 字节）直接解析成功；去掉 EXIF 后的 185,306 字节也能从 alpha 隐写解析。对这两份相同字节，入口传入 `.webp` 文件名均返回 null，只改变传入的名称为 `.png` 则读到完整元数据，没有发生转码。

真实弹窗检查同时确认：传入入口的 null 结果即显示缺失提示且不可导入，传入底层服务返回值则正常显示导入选项。相关 5 个生产文件与已安装 **2.2.4+77** 的冻结输入一致；11-01 三项已完成、未安装的源码哈希也保持。

## 最小修复建议

删除通用图片元数据检测函数中仅允许 `.png` 的文件名判断，直接复用现有按签名解析的服务，并补齐 WebP 两轨和扩展名不匹配的入口回归。不要再增加一套扩展名白名单或解析器；PNG 专用的 Vibe 载体检测继续按其格式处理。

仅确认拖入／粘贴通用入口的明确缺陷，没有原图时不将它断言为所有 WebP 或用户其他导入入口的唯一原因。等待用户确认开工。
