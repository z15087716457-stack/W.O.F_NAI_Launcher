已随 [2.3.2+97 本机更新](../.dart_tool/local-2.3.2-build97-20261111/final-verification.json)交付；下文保留实施与隔离验证时的记录，真实窗口体验待用户验收。

2026-11-11。用户反馈普通窗口右侧外边框有时拖动卡顿，松手恢复，内部栏间分隔线正常；Agent 展开／收回偶有抽动。本批修正源码，桌面仍为 2.3.2+96，未安装或重启用户 Studio。

## 已确认的问题与改动

`MainShell` 的 `IndexedStack` 会给隐藏的保活分支重新布局。原有 `TickerMode` 只暂停动画，窗口尺寸变化仍传进本地／在线图库、Vibe 库、精准参考库、块库和标签百科。进入过哪些页面会影响后续外窗缩放负载；这与旧实验只测首次进入生图页的覆盖缺口一致，但不能据此断言所有偶发卡顿均来自此处。

新增 `RetainedBranchViewport`，在隐藏期间保留分支上次的布局约束和 `MediaQueryData`，再次显示时同帧传入最新值。保留原来的页面实例、滚动位置、输入内容和动画暂停机制；活动页始终按真实尺寸布局。`ConstraintsTransformBox` 只传递约束，不缩放画面，也不缓存页面截图。其他非保活分支继续按原策略销毁重建。

改动为路由接线、新视口组件及两处测试。未修改原生窗口、Agent 控制器／动画时序、画质、材质或状态契约。Agent 原生扩窗／还原也会改变路由约束，因此同样排除隐藏页面的额外布局；本批未单独复现并宣称修复所有一帧抽动。

## Windows 隔离对照

登记 SDK 的同一个 Profile 程序以参数切换原策略／新视口。使用真实生图、Vibe、精准参考与块库页面组件，内存设置、200 张合成历史和合成图片；先逐个进入三个库页，再回到生图页。没有运行正式启动链、读取账号／正式索引或请求生成接口。

每轮右边框 480 步，原生定时器驱动 `WM_SIZING`／`SetWindowPos`；首尾发送进入／结束缩放消息。它没有调用系统真实鼠标拖动的模态循环。两次 before→after 交替，144Hz 显示器、客户画面 1584×961，其他桌面程序保持运行。

| 指标 | 第一轮原策略 → 新视口 | 第二轮原策略 → 新视口 |
|---|---:|---:|
| 每个隐藏库页布局次数 | 464 → 0 | 464 → 0 |
| 原生单步 P95 | 41.30 → 35.94 ms | 41.46 → 34.29 ms |
| Flutter 构建 P95 | 13.22 → 8.34 ms | 13.20 → 7.93 ms |
| Flutter raster P95 | 23.33 → 23.93 ms | 23.39 → 22.17 ms |

原生单步 P95 改善约 13%／17%；主要排除了无用的 CPU 布局工作。此指标是窗口线程完成一次尺寸变化的耗时，不是显示 FPS；活动画布仍有实际布局和渲染成本。合成数据不能替代用户原窗口的偶发问题验收，待明确更新指令后交付桌面验证。
