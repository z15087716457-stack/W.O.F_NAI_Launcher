## 改动

- GitHub 请求边界提取 HTTP 状态、JSON `message` 和限流响应头。403 仅在剩余额度为零、提供 Retry-After 或实际消息明确说明限流时标记限流；429 同样显示限流。Retry-After 秒数优先，否则主限流使用额度重置时间，界面标明本地时间。
- 既有检查服务组织本地化提示，provider 分开保存正文与原始异常。普通 403 保留服务器实际原因，不误报限流；完整异常链与响应正文交给“复制详情”。
- 既有弹窗取消错误区域固定的 120px 高度，保留最小高度与现有滚动容器，长正文不再溢出或压住按钮。复用现有复制文案及提示，没有增加弹窗或独立错误系统。

截图没有 GitHub 的原始响应正文及限流头，因此无法确定该用户此次 403 的实际原因。修复不会绕过服务端限制，也没有新增自动重试、镜像或令牌配置；现有检查间隔与后台静默行为保持。
