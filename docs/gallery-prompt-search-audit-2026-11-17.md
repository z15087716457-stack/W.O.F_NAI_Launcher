# 图库提示词搜索审查与收口建议

> 当前状态：用户已确认方案，源码实施与验证已完成，见[完成核验](gallery-prompt-search-2026-11-17.md)。以下保留实施前的审查依据，尚未更新桌面。

2026-11-17。用户反馈从图片复制提示词片段后搜不到结果，并要求检查优化方式和积累的维护问题。本轮只读检查生产代码，在隔离SQLite图库运行探针；搜索实现尚未修改，也未操作正式图库或索引。

## 已复现的问题

1. **查询与检索文本使用不同表示。** 原文`A girl with 1.3::silver hair:: holds a book.`复制到搜索框后，查询侧去掉权重，数据库`positive_prompt_text`和FTS仍保留权重。整句及去掉权重的自然写法在advanced、FTS、metadata text和实际GalleryFilterService四条路径全部零命中，连来源图片也搜不到。
2. **全局标签表隐式决定普通输入的搜索模式。** `advancedSearchResult`发现某个分段出现在图库标签表时，会改用完整标签身份，并提前与其他条件求交。向另一张无关图片登记`2koma`后，查询`-1.5::chibi, dolls, comic, reference sheet, 4koma, 2koma`从有结果变为零结果；同一图库的FTS／metadata text仍能命中。原因是跨逗号权重组末尾的`2koma::`没有开头数字权重，该片段的闭合符不会被当前normalizer移除，完整标签判断失败。在末尾补回`::`反而又能命中，说明是查询分支问题。
3. **同一搜索行为由多条流程承接。** GalleryFilterService遇到逗号先执行一套分段流程，可能先查元数据筛选，再做分段搜索，随后按ID重新读取图片；无逗号直接进入advancedSearchResult，后者已经能够返回路径并处理全部文本条件。基础搜索、分段、FTS、完整标签判断还各有自己的处理和空查询契约，维护时容易只改到一处。

现有`gallery_search_behavior_test.dart`明确把“登记过标签后，普通输入切换为完整标签匹配”当作预期行为。它验证了代码约定，却没有验证“从图片复制提示词片段应能找到该图片”这个使用目标。因此历史回归通过不能排除本次问题。

## 建议的统一规则

- **普通搜索框保持稳定的内容搜索。** 匹配文件名、正向提示词／角色正向及现有可检索信息，和全局是否登记某个标签无关；手动标签可作为匹配来源，不能改变其他内容的匹配规则。点选生成的标签chip继续做完整标签筛选。此处是建议的行为调整，会取代上述旧测试中的隐式模式切换。
- **共用一套输入／索引归一化。** 只对派生检索文本处理NAI权重、空白与空格／下划线形态；原始提示词、角色、负向和图片元数据保持。整段加权句子、跨逗号组、手动换行与片段首尾不完整的权重均需覆盖。旧数据沿现有SQLite／FTS拥有者修正派生文字索引，不依赖重建RAG向量。
- **共用一条图库筛选执行路径。** 逗号继续表示多条件同时满足；空格保留短语含义，例如`blue eyes`是一个短语，不能盲目切成两个标签。图库范围、候选路径、日期、收藏、标签chip等约束统一处理，最后排序／限制；保留取消、过期请求保护及超过10,000项的完整结果，退役分段入口中的重复查询和记录回读。
- **RAG继续作为语义补充。** 当前实现已经先保留基础结果，再追加图库RAG结果；只有图库索引存在且可用时才会补充。普通提示词检索应独立可靠。本问题属于图库文字搜索，与已对齐DanbooruSearch的标签语义搜索不是同一个入口。

## 建议的验收

从同一张图复制完整／局部／带权重／空格或下划线形态的提示词，应命中来源图；基础与角色正向都覆盖。无关图片增删手动标签不能让原有文本命中消失。普通内容搜索与标签chip的行为分别验证；负向词不泄入结果，目录范围、收藏、日期、排序、取消及无RAG场景保持。纯分隔符的视图行为应明确，低层空查询返回和界面“没有文本约束”不能混为同一接口契约。

证据：`.dart_tool/gallery-prompt-search-20261117/probe-results.json`包含5张合成图片、12组查询、四个实际查询入口的结果；`search_probe_test.dart`和`probe.log`保留隔离探针。`before.json`与`before/`冻结当前源码／测试，供后续实施比对。本轮未修改生产搜索代码、用户提示词、正式数据、桌面程序或模型配置。
