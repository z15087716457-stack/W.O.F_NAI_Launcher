The native Vibe and precise libraries now support entry update/delete, with Vibe category query/create/update/delete. Updates accept explicit desired values and a fresh entry version. Bundle parameter changes require a child index. Category writes require a fresh category/membership version, check sibling names and ancestor cycles, and use the native reparent/membership behavior. Precise references have no native categories. Applying a reference records native usage once after the draft commit; a usage persistence failure reports separately so the applied reference is not retried.

Before mutation, the binding exports the original reference file and complete native record into a fresh workspace output folder. It then rereads the source/version and checks Stop, lifetime and active jobs. A missing source file still permits metadata management or deletion, with its missing status and stored native data backed up. Invalid files are reported explicitly and their original bad bytes can be retained for recovery. Legacy inline pixels, thumbnails, encodings and bundle data are included in the disk backup, never the model summary. Each backup file is bounded to 64 MiB; failure or an oversized backup prevents the native write. There is no automatic restore or new transaction journal.

The native operations finish after admission. Partial commits return `ok=false`, the applied fields and backup, without rolling back other user edits. If unavailable, it returns `encoding_required` before mutation and guides the model through applying the reference, editing the draft, visible generation quotation/approval, and saving the encoded result. It never calls the native parameter-save helper that can encode at a cost. Updating native bundle parameters preserves compatible encodings for additional models and variants and leaves other children intact.
