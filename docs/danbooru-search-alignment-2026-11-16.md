## 检索与启动器适配

`tag_query.py`恢复英文复合标签／变体、中文显式短语边界、jieba词表与停用词。`tag_search.py`使用精确f32矩阵计算；意图权重只分配四路候选，排序使用原始语义分与全语料热度归一化，沿用参考的0.35预筛、0.45终筛、四位舍入、整句一致性修正、别名归并顺序、分句保底及可选分组规则。

四路输入为英文名（下划线转空格）、中文同义词、释义和中文核心词。参考数据的空字段也保持参考四路表示；启动器新增标签只编码实际存在的字段。检索仅使用明确输入，不掺入用户提示词；已有标签继续排除。

Ctrl浮层保留本地精确名称／译名和最多4个真实名称前缀结果，之后显示语义结果并去重，避免`watercolor`等名称片段被语义结果挤掉。这一展示适配不注入Python核心评分；Agent按名称查找仍使用`tag_query`。选择后冻结迟到结果、草稿保护、取消、空框本地共现及原有提交路径保持。

检索矩阵缓存在CPU（实际worker设置3个Torch线程），嵌入仍使用已选Gemma设备。未改变向量时不因其他集合写入或无变化的同步反复加载矩阵；发生来源变化时拒用旧字段向量。保存继续经过原共享池／检查点拥有者。

## 参考数据之外的标签

参考集是基础资料，不限制标签范围。读取当前活动catalog与运行库的完整并集：

| 资料 | 接入方式 |
|---|---|
| 参考词条 | 直接使用其中文名／同义词与释义；热度、类别跟随本地活动标签元数据 |
| 其他本地标签 | 英文名称先进入检索；有英文Wiki时增加释义向量，无需先翻译 |
| 已有公共中文补充 | 为参考集外的标签补中文核心词、同义词及释义 |
| 个人语义资料 | 优先应用已保存字段；释义仍核对Wiki来源hash，删除补充后恢复基础资料 |

只读核对的本地标签为638,857个，合并参考集独有106个后共638,963个。当前可用视图：名称638,963、中文同义词54,624、释义256,196、中文核心54,624，总计1,004,407条向量。这是应建数量，不是已建立正式索引。

后续沿用现有按需翻译／个人语义资料链：先补可读中文资料，再由嵌入模型编码变动字段。使用语义修订记录定位变动标签，未变字段复用；不全量批量翻译，不强制联网调用。中文搜未翻译冷门词的效果依赖Gemma跨语言能力，英文名称与已有Wiki可先使用，不能保证每个中文意图都命中。

自动翻译需用户现有开关开启，按当前可见词条补缺；已明确建库、允许自动同步且未暂停时，后续刷新才增量编码新资料。已有中文译文与私人补充继续作为数据使用。退役实现已删除旧上下文截取模块、单向量文本拼装与无调用的Python字面查询；共享数据库和检查点不是旧检索算法。旧协议参数已收口为query、existing、limit及按次选项，孤立分支已清理，见[11-17核验](system-cleanup-2026-11-17.md)。

## 数量与Agent选项

界面所选数量同时作为默认`top_k`和最终显示上限。`top_k`是每个查询按意图分配给各路的候选预算，整句和分段会分别召回；经过去重／类别／阈值与最终截断后不保证凑满。为兼容原界面80条选项，支持预算1–80；参考API的1–50上限在这里作了宿主适配。

`studio_search(source=tags)`增加按次`tag_options`：`top_k`、`popularity_weight`、`use_segmentation`、`target_layers`、`target_categories`。省略时预算跟随`limit`，其余沿用参考默认值；例如返回12条可使用预算40。Agent返回数量仍限制1–50，不读取或改写用户浮层数量设置。参数只影响本次调用，不修改全局设置，不启用RAG、不建库或清库。契约、Dart边界和实际worker已接通，说明见`tool/nai_agent/skills/nai-studio/references/search.md`。
