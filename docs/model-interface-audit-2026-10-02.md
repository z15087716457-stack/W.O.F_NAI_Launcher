# 模型与接口代码审查 · 2026-10-02

本轮沿服务编辑、配置持久化、功能接口选择、凭据读取和协议请求执行检查现有实现。以用户已接受的 `fc4ea2da` 为界面基线，不重新设计页面。

## 已处理的问题

| 问题 | 处理及结果 |
| --- | --- |
| 服务编辑器同时维护页面与已无调用的旧弹窗布局 | 删除旧弹窗入口及非嵌入分支，将组件更名为 `AiServiceEditor`。编辑状态与操作保留在编辑器，模型列表布局移至同库 part 文件。 |
| 旧 `ModelParameterFields` 已无调用，只有档位工具仍被引用 | 删除旧表单；协议支持的思考档位统一放在 `ProviderProtocol` 扩展中。 |
| 保存与删除服务使用不同写入流程；删除在持久化前移除内存配置和密钥 | 收敛为同一服务提交方法，成功后发布状态。失败时恢复已尝试写入的请求设置、密钥及配置，覆盖存储写入后才抛错的情况。 |
| 交叠的旧操作可能回退新操作已保存的凭据 | 串行提交服务变更，读取和写入阶段核对观察到的配置。过期操作明确失败并要求重试，避免覆盖先完成的保存。 |
| 删除预设、导入配置先发布内存状态，失败后状态不一致 | 沿用配置草稿持久化方法，保存成功后发布；写入抛错时尝试恢复当前配置。 |
| 编辑器的 busy/saving 两个布尔量可能不一致 | 用单一操作枚举表示获取、测试和保存。异步保存完成后先检查组件是否仍挂载。 |
| 已保存服务的请求设置尚未加载即可获取或测试 | 获取、测试、保存共用就绪条件，等待安全存储读取完成；读取失败时保留错误并阻止提交。 |
| 提示词与标签执行分别重复加载凭据和请求设置 | 路由选择统一返回明确的服务与模型，再从一个入口加载密钥、Headers 和模型覆盖值。提示词转换仍要求明确绑定，标签任务保留既有回退规则。 |

受影响的生产文件合计从 6398 行降至 6048 行，净减少 350 行；新增回归测试不计入该数字。模型参数编辑、配置提交和协议适配各自保留职责，没有合并具有不同请求语义的协议实现。

## 行为与兼容范围

- 主动获取返回的目录仍是编辑会话中的临时列表，保存不会清空；不自动拉取或填入预设模型。
- 本地模型事实目录只补充已选模型的参数；既有用户覆盖与旧配置迁移保留。
- schema 7、安全存储键、配置导入导出格式和厂商排序保持。
- 固定模型框高、高级定位、方形交互反馈与保存按钮效果保持。
- 旧配置迁移与既有数据操作接口没有按“代码较旧”直接删除；本轮移除的旧布局和旧表单已确认没有生产调用。

服务提交采用可回退的多步写入，不构成跨本地与安全存储的数据库事务。若存储连恢复写入也拒绝，记录不含凭据的回退失败信息并向上返回原始失败；没有宣称断电或所有存储故障下的原子性。
