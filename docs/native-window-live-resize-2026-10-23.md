# 窗口外边框：正常比例实时布局 · 2026-10-23

用户反馈 +45 虽然流畅，但整页随窗口变扁或变窄，随后明确选择“保持正常比例实时布局”，修好先更新桌面、检查后再发 2.1.1。本次替换 +45 的整页拉伸方案，保留此前全部累计更新和内部四条分隔条预览。

## 实现

- `WindowResizeScope` 只监听现有 window_manager `resize`／`resized`，传递拖动阶段；不改变页面约束、MediaQuery、Navigator、内容变换或普通动画。
- 文字、按钮、三条浮动工具栏、侧栏及原图按真实窗口尺寸实时布局，图片维持原比例。
- `ResizeDecorationCache` 仅包中央通道装饰，以及已经模糊的侧栏背景。拖动中保留这些装饰的配置与布局，停止装饰自己的 ticker；第一次实际绘制后按当前 DPR 缓存位图，后续用等比例 cover 裁切绘制。首帧也使用相同的等比例覆盖，因此不会露空边或产生非等比拉伸。
- 松手时释放位图并用最新装饰配置、真实尺寸重绘；组件和状态不移除。隐藏页面不主动截图，组件释放也释放位图；缓存创建使用登记 SDK 的同步图像句柄 API，没有异步捕获链。
- 侧栏 65% 材质、三个浮动工具栏和原图保持。没有新增原生协议、轮询、超时、自动重试、错误兜底或降级开关；没有修改 SDK 或依赖。

## 行为验证

18 项专项组件测试：五组多步窗口尺寸均实时更新约束和 MediaQuery，输入框保持正常高度、编辑器实例与最新草稿保留；非拖动尺寸变化、取消再拖动、DPI 切换、普通动画继续运行、订阅清理均通过。装饰缓存期间不再重画，正常内容继续更新、固定比例区域实时贴靠窗口；松手应用最新装饰。另覆盖开始拖动与改变尺寸同一帧的边缘像素、拖动中释放、隐藏后首次显示、装饰 ticker 单独暂停／恢复。

首次全量为 8536 通过／1 失败／5 跳过，唯一失败来自既有设置页 Vibe 路径测试：固定 30ms 的等待没有涵盖按钮自身磁盘 IO。只修测试等待，保留真实按钮操作和路径断言，等实际显示路径完成后再检查；产品路径逻辑未修改。设置页复测通过，初次全量日志保留为 `regression-initial.jsonl`；最终完整回归另见本机交付。

## 原生隔离对照

沿用同一隔离 Profile 夹具：真实生图页面组件、200 张合成历史、内存设置，不运行应用启动链、不访问账号和正式索引、不请求模型或生成接口。单包参数切换是否挂载阶段 scope；对照组为正常实时布局但不启用缓存，实验组为实时布局加装饰缓存。每轮按右、左、底、右下角各 120 步原生 WM_SIZING／SetWindowPos 驱动，结束发送 WM_EXITSIZEMOVE。

三轮 before→after 交替，144Hz 显示器、初始渲染 1584×961。下表为三轮各自 P95 的中位数：

| 外边框 | 正常布局无缓存 | 正常布局加装饰缓存 | 减少 |
|---|---:|---:|---:|
| 右边 | 37.05ms | 22.54ms | 39.2% |
| 左边 | 36.77ms | 22.02ms | 40.1% |
| 底边 | 37.04ms | 21.97ms | 40.7% |
| 右下角 | 39.11ms | 22.14ms | 43.4% |

拖动期间构建中位数约 4.4–4.7ms → 0.8–0.9ms。

测量值是窗口线程完成原生缩放步骤的耗时，并非屏幕 FPS。用户 Studio 和其他 GPU 活动未停止；每轮保存负载，绝对值只代表本次环境。没有把旧 +45 的整页拉伸测量当作本次结果。
