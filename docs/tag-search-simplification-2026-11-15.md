# 标签搜索精简与重排模型退役调查

本轮按用户要求只调查和汇报。未删除代码／模型、修改配置／索引或安装程序；此前补全双栏80的源码改动保持。桌面和公开版仍为2.4.1+115。相关故障复现见[上一轮调查](tag-expansion-search-investigation-2026-11-15.md)。

## 结论与建议

模型选型已确认：用户明确要求嵌入模型暂时继续使用现有EmbeddingGemma 2，**本轮不引入或切换BGE-M3，后续检索改造沿用Gemma 2。** 当前故障已证明有评分／合并缺陷，未证明Gemma的标签相关性弱于BGE。下文关于标签BGE／其他集合Gemma的双模型方案与资源数字仅保留为历史候选成本分析，不作为施工决定。暂无同数据、同表示、同预算的模型A/B；模型选择确认不代表已授权重构开工。

建议用DanbooruSearch的多视图搜索方案替换标签检索核心，同时退役Qwen重排及已经脱离当前编辑器的旧补全链路。保留现有编辑器、快速补全、中文资料、增量数据更新、词库／Wiki、共现数据与通用资源生命周期；不整仓引入参考项目的网页、账户、API限流、遥测、MCP服务器和画师工作区。

优先按照公开算法设计独立实现一个小核心，避免为抽出少量搜索功能直接引入参考项目整个引擎的依赖。若实际采用其源码，按GPL-3.0保留许可与归属并处理组合分发；当前MIT并不免除上游要求，本轮没有更改许可证。

## Qwen不能只删一个按钮

当前实际调用：

- `engine.py:557–559`：手动实体查询和空框上下文推荐使用Qwen；普通手动标签查询已跳过重排。因此删Qwen本身不会修好此前“刻晴／阴蒂”丢失，仍须替换评分和结果合并。
- `documents.py:229`：Wiki与积木检索使用CrossEncoder；图库参数文字通道也复用该方法。图库视觉通道不使用Qwen。
- Dart `RagController._open`要求embedding和reranker都非空；Python `Models`构造也要求重排路径存在，所有RAG集合共用它。下载清单、设置状态、路径发现、下载进度、协议、五语言文案及相应测试均要同时调整。

建议把文本集合改成现有嵌入相似度排序，保留范围过滤、来源摘要核验、分块及按owner去重；同时清理只为重排保留的32候选上限。标签搜索按新多视图核心评分。空框推荐以当前标签共现为主，手动输入才进行语义搜索；这会改变旧空框“整段草稿语义推荐”的行为，属于明确拟退役功能，尚未实施。

退役后不保留一个默认关闭的旧Qwen分支；已保存的旧配置仅兼容读取并忽略，不写回覆盖用户设置，不自动删除外置模型目录。通用`sentence-transformers`、`transformers`、PyTorch仍被嵌入／图像模型使用，不能把它们当成Qwen专属依赖一并删除。

之前70条生产标签查询、每条3次热测中，仅6条查询／18个热样本使用Qwen；重排阶段中位291.26ms。这是历史同源码实测的阶段统计，不是本轮有／无Qwen质量A/B，也不能据此宣称所有场景提速291ms或相关性不变。文字集合改为无重排后的质量仍需代表性查询验收。

## 按参考方案替换的边界

已核对Space固定源码`f50d563d8b40f126e1509c1291977afd73b173dc`：

1. BGE-M3，英文名、中文扩展词、释义、中文核心词四个向量视图；完整查询与分词／显式片段共用召回与评分。
2. 按意图分配视图预算，跨视图取较好命中，统一相似度／归一化热度，分词时使用完整查询一致性调整。
3. 官方Alias在最终截断之前规范化去重；标签搜索与基于所选标签的共现推荐是两个明确入口。
4. 当前核心只输出一次最终顺序，UI不再把不同评分的结果拼接后抢占名额。自动补全继续走轻量名称入口，Ctrl和Agent主动语义查询共用标签核心。

拟退役当前标签检索中的拼接全文单向量表示、按类别穿插候选、精确核心词决定实体路径、非召回名称默认0分、Qwen条件分支及UI末尾名称回落。保留来源规范化／当前数据核验和实际库条目限制，不能为了排序更像截图而返回已失效名称。

共现现行实现已在编辑器与Agent间共用；它不是本次手动搜索丢失的原因。参考项目NPMI使用估算总帖数，现有边际频数和边数据来自不同快照；本次建议先保留正常共现接口与数据，不为形式一致更换评分。新搜索内核不引入网页服务、计数器、API Key、遥测与服务器并发层。

## 模型和索引成本

| 资源 | 查得大小／事实 | 含义 |
|---|---|---|
| 当前Gemma权重 | 1488915288字节，约1.49GB | 图库视觉／以图搜图需要它；继续供Wiki、积木及参数文字检索使用 |
| 当前Qwen权重 | 1191588280字节，约1.19GB；完整管理下载约1.21GB | 可停止下载与加载，移除必需项 |
| BGE-M3官方PyTorch权重 | 2271145830字节，约2.27GB | 若标签对齐参考模型，新增它，净模型权重约增加1.08GB；代码更简洁不等于下载量更小 |
| 当前标签向量 | 638857个768维Gemma向量 | 无法作为1024维BGE向量使用 |
| 当前中文语义资料 | 54407条 | 资料覆盖不能冒充整个主标签库覆盖 |

BGE用文本嵌入，不能替代现有Gemma的图像嵌入。若模型对照证明标签BGE有明确优势，双模型候选方案为标签BGE、其他文字／图像Gemma，两者共享现有Worker资源释放／取消约束并按需加载。当前优先验证单一Gemma的多视图方案，不预先引入第二个嵌入模型。

四路FP16、1024维的裸矩阵估算：54407条约425MiB；把638857条全部机械复制四路约4.87GiB。此数仅为向量元素，不包含模型、索引结构、元数据或查询中间内存，更不代表实测峰值。建议先在语义资料池验证对齐效果，完整主库的名称／别名检索继续覆盖全量；字段不存在时不制造重复的“中文”视图。扩大语义覆盖与索引装载方案应按实际字段和实测预算确定。

新的标签表示需对应标签索引，即使继续使用Gemma，也不能将旧拼接全文向量冒充四个新视图；参考实现基于BGE的相似度阈值不能原样套用。先在隔离目录验证，再切换标签来源。保留Gemma其他集合的向量与指纹、用户草稿及原数据，不重建Wiki／块／图库。本轮仅现查旧池集合：tags638857、blocks726，Wiki／图库未见向量；代码仍有这些可用能力，不能把当前没建库当成可以删除功能的理由。

## 后续实施顺序

先冻结失败及正常查询集，完成独立多视图核心的同条件对照；再把Ctrl和Agent接到一个最终结果接口，同时退役旧调度／Qwen及其设置、管理和下载接线。使用现有键盘、输入法、原文编辑、取消／迟到结果、语言与资源释放回归验收，最后才做桌面交付。测试门槛应核对期望标签的排名、覆盖与延迟，不能只断言“有80项结果”。本轮不执行上述改动。
