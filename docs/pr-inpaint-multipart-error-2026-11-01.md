# PR + 局部重绘请求与错误展示修复

2026-11-01。用户反馈启用 PR 后局部重绘返回 400，而卡片只显示“错误”。本轮不触发真实生成。

## 原因与修改

图生图／局部重绘已有共用 multipart 请求入口，只上传了底图与蒙版；精准参考仍以 Base64 留在 `director_reference_images`。同一请求成为 multipart 后，服务端按附件名解释这些值，报 `API_ERROR_400|image field references unknown form part`，并回显了整段图片数据。用户提供的详情超过 230 万字符。

修复留在原 `_requestBody` 内：将精准参考 PNG 作为独立附件上传，数组按原顺序引用附件字段名。文本生图仍使用原 JSON 路径；Vibe 编码、参考类型、强度、保真度、底图与蒙版及用户原参数保持。[官方说明](https://docs.novelai.net/en/image/precisereference/)也明确精准参考可用于局部重绘，这不是功能组合限制。

现行 `generation_data_wiring` 只填写通用标题与复制详情，漏接了旧视图已有的错误解析。将原解析移到一个共用函数，现行与旧视图复用；卡片直接显示 HTTP 代码和服务端原因。至少 256 字符的带引号 Base64 回显在卡片中省略为 `"…"`，其他超长原因限制为 240 字符；复制详情继续保留完整原文。没有增加弹窗、折叠按钮或新的错误系统。

## 验证与状态

- 修复前隔离重现 4 条失败路径：图生图／局部重绘 × 流式／非流式，PR 数组均引用不存在的表单附件。
- 修复后请求构造、API 服务、错误映射及实际 provider 接线共 74 项通过；本地化解析 4 项、真实字体下的错误卡片实绘 2 项通过，总计 **80 项**。多个 PR 的顺序、附件像素、类型、强度、保真度、底图／蒙版与原参数均核对。
- 8 个相关文件分析无问题；2.4 MB 合成图片回显不会撑大错误卡，完整复制详情保持。实绘是合成数据的组件验证，不冒称用户窗口或真实生图。
- 本次没有请求真实模型或 NovelAI，也没有改写用户提示词、角色、草稿或正式索引。证据在 `.dart_tool/pr-inpaint-error-20261101/verification.json` 和 `captures/`。
