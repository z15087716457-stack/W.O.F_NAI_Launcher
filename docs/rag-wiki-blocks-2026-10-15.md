## 可用行为

- RAG 设置增加 Wiki、提示词块两个独立开关与索引管理。默认关闭；每个来源首次均先预览文档数、片段数，再由用户点击开始。之后自动增量，支持部分可用、暂停／继续、单独清除／重建；关闭保留索引。
- Wiki 搜索先显示原有名称匹配，再补充 Gemma 语义召回与 Qwen 文字重排结果。目录、收藏／收藏集、分类与“有正文”筛选保持有效；“无正文”筛选只走普通搜索。空查询不调用模型，查询变化、返回历史、离开页面会取消或丢弃旧结果。
- 提示词块接入主页面、生成页侧边栏和块选择器。原有文字命中优先，语义补充按重排顺序显示；遵守当前文件夹及子目录、收藏集、收藏、归档与快捷筛选，不返回已删除块。编辑已保存内容会使旧片段失效，使用次数／收藏变化不重嵌入。
- Wiki、块库和块选择器搜索框尾部显示真实 RAG 状态。可用时亮起；部分就绪有提示，查询／冷启动时显示小动画，未就绪时弱化。关闭对应来源时隐藏，普通检索不等待模型。
- 标签、Wiki、块库索引分别存储，共享一个本地模型进程与资源调度。后台任务按来源暂停，交互请求先于下一批建库；本地超分可让出全部 RAG 模型显存。一个来源清除不影响其他来源。

## 数据与边界

Wiki 只读现有百科正文和标签分类；长正文按 1200 个 Unicode 字符、重叠 120 字符切片。块库由 Dart 导出稳定的派生 JSON，只包含已保存、未归档块的 ID、标题、标签、正负面正文及无需复核的阅读译文。Hive 不交给 Python 直接读取，不导出图片、原文件路径、生图参数、使用量或编辑草稿。

向量位于应用数据目录 `rag/v1/indices/wiki-v1/`、`blocks-v1/`，再按模型指纹隔离；块派生输入位于 `rag/v1/sources/blocks.json`。SQLite 向量、ANN 恢复、源签名及首次确认机制复用首版。暂停期间源有变化，继续时以新快照重新规划增量，复用仍有效的向量。查询前核对实时内容摘要，旧片段不能冒充新内容。

文字查询有独立的 256 Gemma-token 上限；**提示词推荐的两种 120-token 窗口没有改变**。全局搜索先取最多 160 个片段、去重到最多 32 份资料后重排；范围查询在允许的 ID／类别内排名，避免小目录被全局 top-k 过滤丢失。返回有界 ID／标题／片段，不把查询存入索引。范围查询目前对范围内已存向量计算相似度，超大范围性能尚未全库实测。

模型与专用依赖沿用 [首版报告](rag-tag-context-2026-10-15.md)。本次真实验证使用本地 Gemma／Qwen、RTX 4080 与 CUDA；CPU 路径可配置，本次未做完整 CPU 性能测试。只加载文字编码器，原始图片／音频权重未改。工作区、图库与 Agent 工具仍留待后续批次。

本批用户明确允许补齐锁定界面的可选状态字段和尾部标识，因此仅改 `blocks_contract.dart`、`blocks_wall.dart`、`blocks_dock.dart`、`ui_inputs.dart` 并新增纯展示 `blocks_rag_badge.dart`；provider 读取留在 wiring。其余锁定 UI、原中文基准图和已有 `DEVELOPMENT.md` 修改保持原样。
