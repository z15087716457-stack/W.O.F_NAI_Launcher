# Ctrl 标签扩展与 DanbooruSearch 检索对照

本轮为只读调查，未修改搜索实现、用户草稿、配置或索引，未构建／安装／发布。此前双栏补全上限80的源码改动保持，桌面及公开版仍为2.4.1+115。

## 已复现的结果丢失

使用当前真实来源数据库、638857条标签的已有ANN、本地EmbeddingGemma／Qwen权重执行生产`Engine.search`。中文名称SQL和Dart弹窗最终合并按当前实现镜像；未调用会迁移／恢复／保存索引的构造器。六组查询为阴蒂、女孩、刻晴、机械义肢、中国风古装、雨夜，结果上限80、已有标签为空。

| 输入 | 本地名称命中 | 最终扩展结果 |
|---|---|---|
| 阴蒂 | 63条 | 漏掉17条名称命中，包括clitoral_piercing；前12项与用户截图一致 |
| 刻晴 | 4条 | keqing及两套服装标签全部丢失，前列却为clock_eyes、cosplay和其他标签 |
| 女孩 | 80条 | 漏掉38条名称命中，2girls被重排到80项之外；同名角色被当成精确实体置顶 |

名称命中不应一概优先于语义结果，例如“雨夜”名称检索也能误命中含同样汉字的人名；表中的丢失数量不是所有结果都应固定置顶的质量指标。角色本名及对应服装、查询词直接指向的具体标签被丢弃，才是这里可核实的问题。

阴蒂、两种穿孔标签和三种刻晴标签在当前来源及正式索引中均存在，六项摘要均与实时来源一致；索引基础来源签名匹配。所有登记数据库／ANN的大小与mtime保持，不存在本次操作导致的索引重建。不能把这些症状归因于标签尚未增量同步。

## 当前链路的具体问题

1. 输入补全直接使用`LocalTagExpansionService.search`的名称／同义词／英文匹配结果。Ctrl扩展在此之上再进入RAG和界面合并，结果并不等价。
2. `tool/rag/engine.py:557`的手动非实体搜索不走Qwen，直接读取ANN候选的`semantic_scores`。名称命中若没有被ANN召回，默认分为0。刻晴三个角色／服装项、clitoral_piercing均实际走到了这一分支并得到0分。部分实体通道使用原始相似度，视觉通道还叠加热度项，分数来源也不同。
3. 实体意图只依据完整精确名称匹配。`刻晴`与中文核心词`刻晴（原神）`不相等，因而没有识别出角色意图；反过来`女孩`完整等于某个角色的核心词，便触发实体路径。这是同名／后缀判定的质量缺陷。
4. `tag_expansion_wrapper.dart:779`把精确名称、RAG结果、其余名称结果依次合并后截断。RAG已填满80项时，排在后面的名称回落无法补回漏项。
5. 手动搜索还会在RAG完成前隐藏非精确名称命中。当前检查没有复现永久空列表；但等待、取消和稳定结果发布应与最终排序一并设计，不能只看查询函数返回了数据。

上述结论来自生产函数执行与阶段变量追踪；原始条目、分数和最终排名保存在`.dart_tool/tag-expansion-investigation-20261115/local-results.json`，源文件摘要及只读核验见同目录`verification.json`。

## 参考项目的实际差异

核对用户给定的[Hugging Face Space](https://huggingface.co/spaces/SAkizuki/DanbooruSearch)，本次固定源码提交为`f50d563d8b40f126e1509c1291977afd73b173dc`；对应项目为[SuzumiyaAkizuki/DanbooruSearchOnline](https://github.com/SuzumiyaAkizuki/DanbooruSearchOnline)。只下载必要文本源码供阅读，没有启动服务、安装依赖或下载模型／向量。

- 参考实现默认BGE-M3，英文名、中文同义词、释义、中文核心词各有独立向量视图；当前客户端为Gemma的每标签单一拼接表示。中文资料虽已复用，检索表示没有对齐。
- 参考引擎按查询意图为各视图分配召回预算，多路合并时保留同一标签的较好分，再使用相似度与归一化热度评分；启用分词时还有完整句子的一致性调整。
- 官方Alias在截断前规范化和去重；共现推荐有独立入口。界面没有再把另一组原始候选拼到已经截断的语义结果后面。
- 其当前`top_k`在内部按意图权重分摊给视图，不可照README的简述当作每路固定取满80；阈值也依赖其模型与数据，不能直接移植到Gemma。
- 本轮没有调用参考站搜索API；在线效果依据用户截图，架构依据下载的固定源码。未完成BGE与Gemma在同数据、同预算下的本机A/B，不能据此宣称任何查询都将改善。

## 建议的重构范围（尚未开工）

- 收敛标签搜索核心：名称／别名命中和多视图语义召回进入同一候选集合，统一评分、规范化、去重后只截断一次；不再用缺失ANN分数0惩罚可靠名称命中，也不由弹窗二次抢占名额。
- 按参考项目的英文／中文名称／释义／核心词分路方案先做隔离对照，明确模型与向量表示，再决定正式替换；以这次失败样本加普通标签、角色、模糊描述的固定查询集作为验收，不能仅确认“有结果”。
